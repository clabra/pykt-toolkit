# Validation Strategy for GTransformer

## Overview

This document outlines a **rigorous yet straightforward** validation strategy for demonstrating that gTransformer achieves interpretable knowledge tracing through theory-guided grounding. The approach follows standard practices in educational data mining and interpretable machine learning, avoiding unnecessarily complex approaches while maintaining scientific rigor suitable for top-tier publication (JEDM, IJAIED, LAK, AAAI).

## Design Philosophy

**Principle**: Use familiar, well-established validation methods executed thoroughly rather than novel, complex frameworks that may confuse reviewers.

**Goals**:
1. Prove grounded parameters are pedagogically meaningful (correlation with theory)
2. Demonstrate each grounding component contributes value (ablation studies)
3. Show latent representations encode interpretable structure (visualization + sensitivity)
4. Validate practical utility through case studies (actionable diagnostics)
5. Compare against baselines to establish value proposition

## Validation Framework

### Section 1: Parameter Recovery Accuracy

**Research Question**: Do the model's predicted BKT parameters ($p_{L0}$, $p_T$) match theoretical expectations from fitted BKT?

#### 1.1 Correlation Analysis

**Metrics**:
- **Pearson correlation coefficient** (r) between predicted and oracle BKT parameters
- **R² (coefficient of determination)**: Proportion of variance explained
- **Mean Absolute Error (MAE)**: Average absolute deviation from oracle
- **Root Mean Square Error (RMSE)**: Sensitivity to large deviations

**Granularity**:
- Per-skill analysis (show consistency across different knowledge components)
- Per-student archetype (struggling vs. advanced learners)
- Temporal evolution (early vs. late in learning trajectory)

**Visualization**:
- Scatter plots: Predicted vs. Oracle parameters with regression line
- Distribution plots: Histogram overlays of predicted vs. oracle distributions
- Heatmaps: Correlation matrix across skills

#### What We Have:
✅ **Model outputs**: `gtransformer.py` already produces grounded parameters ($p_{L0}$, $p_T$) via semantic axes projection (lines 283-328)
✅ **Oracle targets**: BKT soft labels generated by `examples/generate_bkt_soft_labels.py`
✅ **Probe predictions**: Linear probes (`self.probe_l0`, `self.probe_t`) when `active_grounding=1`
✅ **Evaluation infrastructure**: `pykt/models/evaluate_gtransformer.py` handles test-time inference

#### What We Need to Implement:

**Script**: `examples/validation/validate_parameter_recovery.py` (IMPLEMENTED)

**Functionality**:
1. Load trained gTransformer checkpoint (e.g., Exp 948799)
2. Run inference on test set to extract:
   - Grounded parameters from semantic axes (`p_l0`, `p_t`)
   - Probe predictions from linear heads (`p_l0_probe`, `p_t_probe`)
   - Oracle BKT targets from soft labels
3. Compute metrics: Pearson $r$, $R^2$, MAE, RMSE
4. Generate recovery scatter plots for probes (Structural Validity evidence)
5. Save summary JSON and per-skill CSV metrics

### Section 2: Ablation Studies

**Research Question**: Which architectural components are necessary for achieving interpretability without sacrificing performance?

#### 2.1 Component Necessity

**Already Completed** (documented in `benchmark_paper.md`):

| Configuration | Grounded | Probing | Personalization | Test AUC | Purpose |
|---|---|---|---|---|---|
| Baseline (123509) | ❌ | ❌ | ❌ | 0.7838 | Maximum performance ceiling |
| Grounded (090230) | ✅ | ❌ | ❌ | 0.7800 | Output interpretability cost |
| Grounded+Probing (334772) | ✅ | ✅ | ❌ | 0.7786 | + Latent interpretability cost |
| Full (948799) | ✅ | ✅ | ✅ | 0.7785 | + Individualization cost |

**Key Findings**:
- Grounding costs 0.38% AUC (0.7838 → 0.7800)
- Probing costs 0.14% additional AUC (0.7800 → 0.7786)
- Personalization costs 0.01% additional AUC (0.7786 → 0.7785)
- **Total interpretability cost: 0.53% AUC** for full pedagogical transparency

#### 2.2 Loss Component Ablations

**Research Question**: Are all loss components necessary?

**Experiments to Run**:
1. **λ_ref only** (remove λ_init, λ_rate): Test if BKT output alignment alone maintains grounding
2. **λ_init + λ_rate only** (remove λ_ref): Test if parameter regularization alone is sufficient
3. **Varying λ_probe** (0.0, 0.5, 1.0, 2.0): Find optimal strength for probing constraints

#### What We Have:
✅ **Loss infrastructure**: Multi-component loss in `gtransformer.py`
✅ **Ablation data**: Four distinct experiments (123509, 090230, 334772, 948799) covering the evolution of the architecture.

### Section 4: Sensitivity Analysis (Causal Validation)

**Research Question**: Do perturbations along learned pedagogical axes produce theoretically expected behavioral changes?

#### 4.1 Interventional Analysis

**Experiment Design**:
1. Extract latent vectors $z$ for test interactions
2. Identify probe weight vectors $\vec{W}_{L0}$, $\vec{W}_T$ (the "pedagogical axes")
3. Perturb $z$ along these axes: $z' = z + \delta \cdot \frac{\vec{W}}{||\vec{W}||}$
4. Measure effect on prediction: $\Delta P(correct) = P(y|z') - P(y|z)$
5. Plot: Perturbation magnitude ($\delta$) vs. prediction change

**Expected Behavior**:
- Increasing mastery direction ($\delta > 0$ along $\vec{W}_{L0}$) → **monotonically increases** $P(correct)$
- Increasing learning rate ($\delta > 0$ along $\vec{W}_T$) → More responsiveness to recent correct answers

#### What We Have:
✅ **Probe vectors**: `model.probe_l0.weight`, `model.probe_t.weight` (when `active_grounding=1`)
✅ **Forward pass**: `gtransformer.py` can process perturbed latent vectors
✅ **Partial implementation**: `examples/calc_structural_metrics.py` has causal intervention loop (lines 95-115 in demonstrations.md)

#### What We Need to Implement:

**Script**: `examples/validate_sensitivity.py` (NEW, simplified from `calc_structural_metrics.py`)

**Functionality**:
1. Load trained grounded model
2. Extract probe weight vectors
3. Run perturbation sweep: $\delta \in [-3, -2, -1, 0, 1, 2, 3]$ (in standard deviations)
4. For each $\delta$:
   - Perturb latent vectors along $\vec{W}_{L0}$ axis
   - Recompute predictions
   - Record average $\Delta P(correct)$
5. Compute **monotonicity**: Spearman rank correlation between $\delta$ and $\Delta P$
6. Generate sensitivity curve plot

**Usage**:
```bash
python3 examples/validate_sensitivity.py \
    --exp_dir experiments/20260116_120815_benchpaper_948799/gtransformer/assist2009/fold_0 \
    --output_dir validation_results/sensitivity \
    --perturbation_range -3,3 \
    --n_samples 500  # Subsample for efficiency
```

**Expected Output**:
- `sensitivity_curve_l0.png`: δ vs. ΔP(correct) for mastery axis (should be monotonic increasing)
- `sensitivity_curve_t.png`: δ vs. prediction change for learning rate axis
- `sensitivity_metrics.json`: Spearman ρ, monotonicity score, mean effect size

**Control Experiment**: Run same analysis on baseline model with **post-hoc trained probes** to show grounded model has stronger, more interpretable structure.

### Section 6: Baseline Comparisons

**Research Question**: Does gTransformer provide unique value compared to existing approaches?

#### 6.1 Three-Way Comparison

| Model | Test AUC | Interpretability | Individualization | Use Case |
|---|---|---|---|---|
| **BKT** (Exp 305377) | 0.6097 | ✅ High (symbolic) | ❌ Population-level only | Theoretical baseline |
| **AKT** (Baseline) | 0.7825 | ❌ Black-box | ❌ None | Predictive ceiling |
| **gTransformer** (Exp 948799) | 0.7785 | ✅ High (grounded + probing) | ✅ Student-specific | Best of both worlds |

**Key Findings**:
- **vs. BKT**: +28.6% relative AUC improvement while maintaining interpretability
- **vs. AKT**: -0.5% AUC cost for full pedagogical transparency
- **Unique value**: Only model providing individualized, theory-grounded diagnostics at near-SOTA accuracy

#### 6.2 Interpretability Comparison

**Experiment**: Can baseline AKT be made interpretable post-hoc?

**Method**:
1. Train linear probes on baseline model's latent space (post-hoc)
2. Compare probe recovery accuracy: Grounded vs. Baseline
3. Metric: MAE and R² for recovering BKT parameters

**Hypothesis**: Grounded model will have significantly better probe recovery because interpretability is built-in, not retrofitted.

#### What We Have:
✅ **Baseline model**: Exp 123509 (AKT-equivalent, ablation='all')
✅ **Grounded model**: Exp 948799 (full stack)
✅ **BKT metrics**: Documented in `benchmark_paper.md`
✅ **Comparison framework**: Table structure exists

#### What We Need to Implement:

**Script**: `examples/compare_interpretability.py` (NEW)

**Functionality**:
1. Load baseline and grounded models
2. Extract latent vectors from both on same test set
3. Train post-hoc Ridge regression probes on baseline latent space
4. Compare:
   - **Built-in probes** (grounded model): Direct extraction
   - **Post-hoc probes** (baseline model): Fitted after training
5. Compute recovery metrics (MAE, R², correlation)
6. Generate comparison table and scatter plots

**Usage**:
```bash
python3 examples/compare_interpretability.py \
    --grounded_exp experiments/20260116_120815_benchpaper_948799/gtransformer/assist2009/fold_0 \
    --baseline_exp experiments/20260115_123509_benchpaper_baseline/gtransformer/assist2009/fold_0 \
    --output_dir validation_results/baseline_comparison
```

**Expected Output**:
- `probe_comparison_table.json`: MAE and R² for both models
- `recovery_quality_comparison.png`: Side-by-side scatter plots (predicted vs. oracle)
- `interpretability_gap.json`: Quantify how much better grounded model is

## Summary: Why This Approach Works

✅ **Familiar methods**: Standard correlation analysis, ablations, visualization - reviewers know these
✅ **Rigorous**: Quantitative metrics + qualitative validation + comparative analysis
✅ **Efficient**: Leverages existing experiments and visualizations
✅ **Clear narrative**: Each validation addresses a specific research question
✅ **Practical**: Case studies show real-world utility
✅ **Conservative**: No exotic geometric frameworks or overpromising

This validation strategy provides multiple independent lines of evidence that converge on the same conclusion: **gTransformer achieves pedagogically meaningful interpretability with minimal performance cost**. The approach is rigorous without being unnecessarily complex, making it ideal for convincing skeptical but fair-minded academic reviewers.
